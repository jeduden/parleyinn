# ADR-2610142218: The hash

## Context

§8.3 fixes the hash chain (REC-10) and the audit chain (OPS-02) to
RFC 8785 over SHA-256, and ADM-08's canonical digests to SHA-256.
REC-17 asks for a hiding, binding commitment to each event's content
under a random 256-bit commitment key. Ids derive from keys (LANE-01,
LANE-23), and key events carry fingerprints (PRV-12). The core opens
no socket and starts no program (I4), so whatever computes these must
be computation alone. Phase 1 of plan
[2609292012](../../plan/2609292012_m1-record-and-recall/plan.md)
links the first of them into the core executable.

## Decision

| Module | Purpose                                                                                                     | License           | Maintenance                                                  |
| ------ | ----------------------------------------------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------ |
| `sha2` | SHA-256 for the hash chain, ids, fingerprints and canonical digests, and the hash under the HMAC commitment | MIT OR Apache-2.0 | Active; RustCrypto organisation, audited, releases each year |

The commitment is HMAC-SHA-256 (RFC 2104) under the commitment key
over a label and the content's canonical encoding. HMAC is twenty
lines over the hash, written in the `record` crate and tested against
RFC 4231's vectors, so it adds no dependency. Every hashed message
starts with a label of its own (`parinn writer id v1`, `parinn
commitment v1` and so on), so one use never collides with another.

`sha2` is taken at its default features. With `ed25519-dalek` it
shares one `digest` version, so the core links one hash
implementation.

## Alternatives

- **`ring` or `aws-lc-rs`.** Each carries C or assembly and a build
  step, and far more than a hash.
- **SHA-256 written in the core.** Hash code is easy to get subtly
  wrong and slow; RustCrypto's is reviewed and fuzzed.
- **The `hmac` crate for the commitment.** One more crate for twenty
  lines the vectors prove.
- **BLAKE3.** Faster, but §8.3 names SHA-256, and SHA-256 is what
  other implementations and auditors check against.

## Consequences

- The core's reach test allows `sha2` and the crates it brings:
  `digest`, `block-buffer`, `crypto-common`, `hybrid-array`,
  `typenum`, `const-oid`, `cpufeatures` and `cfg-if`, all computation.
- A change of hash is a change of the header's encoding version in
  `meta` (§8.3), never a silent swap.
