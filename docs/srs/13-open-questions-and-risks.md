| OQ-01 | Should ParleyInn control compaction? Options: (a) coexist with native compaction (v1 default); (b) defer compaction via `PreCompact` and manage eviction itself; (c) an API proxy that keeps prompts small (CliffCompaction-style). A proxy is a network component and would conflict with I4, so it could only ship as a separate, independently reviewed component. Option (b) would add a `PreCompact` hook that writes, which OQ-51 (b) does not exclude, since ParleyInn installs only the hooks through which it writes. Closed by the stakeholder (13 October 2026) on S6's findings: v1 takes (a), coexisting with native compaction, and NG1 stands. S6 found, on Claude Code 2.1.296, that a `PreCompact` hook whose command exits 2 blocks a manual compaction and every automatic one (ASM-09). The harness tries again each time it calls the model past its threshold. At the full context window it tries once more, then ends the turn with "Prompt is too long" before any `Stop` hook, and refuses every later prompt the same way, until a compaction is let through or the harness session is cleared. No hook removes anything from the agent's context, so (b) only moves native compaction to the full context window, where it blocks the agent (I9). Blocking also needs a hook handler that exits 2, against OQ-51 (b), and on a manual compaction the model reads that handler's command and stderr, a write outside I2's closed paths. Unbounded (b) is dropped. Kept for later, with UC-006: a bounded veto, whose `PreCompact` hook handler blocks only automatic compactions while the agent is midway through an edit and lets one through at a safe point or after a set number of blocks, and needs OQ-51 (b) revisited; compaction the launcher asks for, where auto-compaction is turned off at install (I7) and the launcher has the agent pin what it must keep and then asks the harness to compact, at a model-token watermark or on "Prompt is too long", each write to the agent needing a principal act or a new closed path in I2; and (c). Taking either of the first two up changes the domain model's Compaction, Hook and Launcher, and I2 for the second, with an ADR and a security review. The published `PreCompact` veto pattern, memory plugins and meta-harnesses such as Omnigent leave compaction to the harness or bound such a veto; none found blocks it for good.                                                                                                                                                                                                                                                                                                                                                                                                  | S6 (closed); the kept options: UC-006                                                                                                                                                                                                                                                                                                              |
