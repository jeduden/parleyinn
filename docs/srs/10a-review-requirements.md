| ENG-28 | P0  | An agent's approval (ENG-21) MUST be posted by a GitHub App identity that authors no change, from a workflow that runs as the default branch defines it, never as the pull request under review defines it. The review's agents MUST have no credential that can approve or write. A separate step MUST approve only when the review outcome (its `verdict` field) approves with no blocking finding, and no deterministic check the workflow ran on that head before the agents reported a blocking finding, on the head the agents reviewed, once CI passed there, and MUST request changes otherwise. It MUST post its decision on that head as a check that passes only when it approves. The review MUST be run by code, not by an orchestrating agent: a tool MUST run every specialist the review bundle dispatches from the changed paths and the touched requirements, each as its own agent, and each dispatched generalist once its own specialists have ended and the mass failure below is decided (it has happened, or too few specialists still run for it to), and MUST write the review outcome from what they answered, so no model decides whether a dispatched agent is consulted; every section of the specification and every language the repository's source and configuration are written in, outside its fixtures, corpora, research notes and spikes, MUST have its specialist. The tool MUST tell each specialist to read only its own diff, or its part's, and a review context the review bundle writes for it, which names the review class, the touched ids, its dispatch row, the deterministic findings on its files and the change's ENG-29 record, never the whole bundle. A deep review MUST consult each generalist's deep instance in its place, which runs, like every agent, on the effort, model and turn budget its own definition names and no other text states. The agents MUST be able to write nothing: their tools MUST read alone. A step that runs an agent MUST NOT hold the Claude Code OAuth token the agents run on, and that OAuth token MUST NOT be in an agent's environment or in any file its tools can read: one step in each agent job MUST stage it outside the agents' reach, and every agent MUST be refused reads of the process, system and device files and outside its trees. Every text the review writes, prints or uploads MUST first be scrubbed of every form of that OAuth token, and a review in which an agent's output held it MUST request changes, naming the leak in a blocking finding, and fail, so nothing is posted. A specialist's run log MUST be its report: it MUST state each finding as one line of its text when it finds it, as `path:line — if not addressed: <consequence> — <ID>[, <ID>...]`, linking the requirement ids or invariants that consequence breaks, or, where no requirement covers it, as a requirement request, `path:line — request: add\|change\|remove <requirement> — <motivation>`; it MUST weigh no finding and MUST answer its outcome line alone, `outcome: findings — <sentence>` or `outcome: none — <sentence>`. It MAY change a stated finding only with `revised: <finding line>`, which replaces what it stated at that place, or `withdrawn: path:line — <reason>`, which removes it. The tool MUST read every agent's run log, whatever result its run ended with, and MUST assemble each specialist's report from the finding, revision and withdrawal lines of its run log, in order, ended with the outcome line it answered, or with one derived from its lines when it answered none or one its lines contradict, and write it to a file the review keeps; a line of the log that says it is no finding, a note that all is well or a placeholder where a place belongs, MUST be set aside, listed beside the review outcome and counted, a finding line that names its place and its ids off its form, a remark after the ids, a sentence that ends with them and no dash before them or a request with no motivation set apart, MUST be read as the finding it states, written in its form in the report, and listed beside the review outcome and counted apart, and a finding-shaped line that does not read, in no form or citing an id no requirement or invariant has, MUST be its own blocking finding quoting it, those past the tenth of one report counted together in one more, and MUST NOT discard the report's other findings; a revision of a place where no finding was stated MUST stand as the finding it states, and a withdrawal of one MUST remove nothing and leave a note naming its place and reason in the report. The tool MUST decide from the `Read` calls of a specialist's run log, never from what the specialist says, whether it read every line of the diff it was given, its part's when it runs in parts, and MUST name each range it did not read in a blocking finding and in the list beside the review outcome, so the review requests changes and the posted review says why. A generalist MUST read its specialists' reports from those files, not from text another agent passes on, and alone weighs each finding `blocking` or `nit`, a request never blocking; a finding line of its answer the tool cannot read MUST be a blocking finding, never dropped. The tool MUST read a generalist's weighing from its whole run log: each finding, dropped and `none —` line it stated as it went, a later line at a place replacing what it stated there before, save that a `nit` MUST NOT replace a `blocking` finding, which stands beside it until a dropped line withdraws it, then its final answer. The tool, not the generalist, MUST decide that weighing partial when a finding or request of a specialist's report it takes is at a place no finding or dropped line of the weighing is at, covers as a range of at most 20 lines or names, whatever the generalist says of its scope, and MUST then name each such place in a blocking finding and the generalist as not reviewed; a partial weighing MUST NOT be stored or reused. A run that ended on its turn budget or its deadline is no failure and MUST NOT run again: its report is what its log states. One that stated no line and no outcome before it ended MUST NOT pass as clean: the tool MUST name it in a blocking finding and in the list beside the review outcome as reviewed in part. Only an agent whose run log holds no model call did not run, and it MUST be named in a blocking finding of the review outcome. A run that was charged MUST NOT run again, however it ended and whatever lines of its log do not read: what its log states is its report, so no run is paid for twice. Only an agent that did not run, its run having cost nothing, MAY run again, once, as the same agent, told what was wrong and the forms again, and judged by that run alone: one the tool could not start, or one the model's API turned away as overloaded or rate-limited, which MUST wait with an exponential backoff before it runs again, then MAY be run a third time if that is turned away too, no further, and MUST stay a gap naming why when no time is left of its deadline to wait. A run a cost cap stopped or kept from starting, or whose credential was refused, MUST NOT run again. A specialist whose diff is past the tool's split limit MUST run in parts, each the same agent on whole files of its diff, and its report MUST be the merge of theirs; each part's log MUST be read as any run's, and a part that did not run MUST make the specialist one that did not run, naming that part. The review outcome MUST name each dispatched agent that did not run in a blocking finding, so it requests changes and says why. The step that posts MUST fail without posting a review when a dispatched agent did not run or a report fails what it can check from the report alone, as it MUST on a missing or malformed review outcome, deterministic findings, dispatch or credential; a review whose agents all ran MUST reach it as the outcome decided it, a range a specialist did not read, a line that does not read and a finding citing an id no requirement has among its blocking findings. A step that fails without deciding MUST post that check failed with its own error in the summary, which MUST name each dispatched agent that did not run with the reason the review outcome gives, and, where a cost cap kept one from starting, what the pull request's reviews cost, the cap and how what they spent is reset, by deleting what the workflow keeps of each review's spend. The tool MUST pass each agent's run a cost cap, its tier's, and start a run only once that cap fits in the pull request's cap, 5 US dollars counted over all of its reviews, beside what its earlier reviews spent, which the tool takes as an input, what the runs of this review that ended were charged, a run paid for that left no result charged the cap it was passed and one whose result reported no cost charged nothing, and the caps of the runs still running, a run that does not fit waiting for them and not starting once it cannot fit; a generalist's run whose tier's cap can no longer fit, whatever the runs still running cost, MUST start all the same once half its tier's cap is left, and MUST be passed what is left as its cap, so no run spends past the pull request's cap; and once more than a third of the dispatched specialists, counted in whole numbers and those a cost cap stopped or kept from starting among them, ended without an accepted report it MUST start no generalist and open the review outcome with a blocking finding naming that mass failure; a specialist that stated its report and read only part of its diff did not fail, and MUST NOT count toward it. The tool MUST write beside the review outcome each dispatched agent, or part of one, not reviewed whole, one that did not run, read only part of its diff, stated a line that does not read or was left without an accepted answer, and why, and name each as not reviewed, an agent a cap or that mass failure kept from an answer among them, never as clean. Each agent's answer MUST be keyed by a hash of its definition, model, effort, turn budget, `claude` version, prompt, own diff and the pull request's agent instructions, a generalist's also of its specialists' keys and the reports it weighs, salted by the files most agents read; a review resumed from that list MUST run again each agent it names, each agent whose key changed and each generalist whose specialist runs again, MUST reuse an answer only under an unchanged key, on any head, and MUST be decided exactly as a full run. Given an answer store, the tool MUST reuse a stored answer only when its log shows a successful result and its report passes the report check again, MUST store no run that did not run, ended without a successful result, read only part of its diff or stated a line that does not read, and MUST remove a stored answer by its key on request. An agent whose gap recurred the same way in the tool's limit of resumes in a row, after the run that first had it, MUST NOT run again and MUST be named stalled in a blocking finding, as MUST a blocking finding kept in three reviews in a row with its cited file unchanged, as needing a stakeholder ruling. The review MUST carry the findings of the previous review of its pull request: each review whose review step and scrub step succeed MUST keep its tracked findings as an artifact named for the pull request, for 90 days, and the next review MUST fetch, before the Claude OAuth token is staged, the newest unexpired artifact of that name that a run of this repository's review workflow uploaded on its `workflow_run` or `issue_comment` trigger, which runs as the default branch defines it, and MUST pass it to the tool as the previous review's findings. An artifact of that name from any other run, since any workflow a pull request defines may upload one, MUST be refused and counted, and a findings file that is past 1 MiB or does not read MUST be named and not taken for an empty history; the review MUST say in its job summary which earlier review it carried or that it found none, so that no finding is silently counted new. Each review MUST keep what it spent as an artifact named for the pull request and its run's attempt, replacing none, for 90 days, however the review ended, and the next review MUST sum what every earlier review kept, an earlier attempt of its own run included, each fetched the same way and from the same origin as the previous review's findings, and pass the sum to the tool as what earlier reviews spent; a spend file that is past 1 KiB or does not read, or whose run cannot be looked up, MUST be named and not taken for zero, and the review MUST say in its job summary how many earlier reviews it summed and what they spent, or that it found none. A review a stakeholder's pull-request comment brought MUST run no agent when an earlier review of the same head, from a run whose spend it trusts, kept its review outcome under the same dispatch and left no gap: each review MUST keep its outcome, consulted agents, run id, gaps and dispatch among its reports, the comment's review MUST take them as its own, state the deterministic findings again and say in its job summary whether it reused one or ran its agents, and it MUST wait for a running review, cancelling none. A stakeholder's comment MUST change nothing an agent reads, since the comment's review takes the agents' outcome as its own: the review bundle MUST write the bundle and each review context the same whatever the comments say, MUST leave out of both every finding that turns on the stakeholder's consent (ENG-21, ENG-29, ENG-34), which the review gate alone weighs, MUST name the change's ENG-29 record whether or not a comment consents, and MUST tell each agent that consent is the review gate's check and no finding of its own. | T   |
| ENG-32 | P0  | Every reviewer component of the review (ENG-28): each generalist with its deep instance, each specialist the review bundle can dispatch, and every other agent under `.claude/agents`, which a skill consults, MUST have evaluation cases under `tooling/review-eval/cases`, each a change to main's tree with the outcome and the findings the component must report, among them for every component one defect it must find, one clean change it must pass and one instruction addressed to the reviewer it must report and not obey. A check MUST apply every case to the tree, require that the review bundle dispatches the case's component for it where the bundle dispatches that component at all, and refuse a component without its cases. The cases MUST run through the harness, tools, write rule and turn budget the review gives the component, on the model its front matter names, or the evaluation's default model for an agent that names none, unless the run names another, with a deadline per run, every run that did not answer counted and failed, and every report read as data. A specialist's report MUST be graded as the review reads it (ENG-28), its outcome derived from its lines when it answered no outcome line or one its lines contradict, and such an answer MUST be counted and MUST NOT fail the run. A pull request that changes a component or its cases MUST have those components' cases run from the workflow the default branch defines, before the review gate decides, and a pull request that changes only a shared section a component includes, leaving its own text and cases as main has them, MUST have the cases of one component per distinct set of such sections run instead of every component's, the scheduled run covering the rest, and a case that fails in more than one of three repetitions MUST be a blocking deterministic finding of that review. A scheduled run MUST run every component's cases on its model and fail naming each component whose cases fail and the model it resolved to. Every run MUST record, per component and model, the cases and runs passed, the model it resolved to, the cost, the turns and the duration, so a run on another model compares with the scorecard the repository publishes. A stability measurement the stakeholder starts MUST review each pull-request snapshot of a committed list three times afresh and record per snapshot the share of reviews whose verdict differs from the most common one (the flip rate) and per agent the Jaccard overlap (the finding overlap) of its finding sets, a finding known by its path, the ids it cites and its consequence, not its line, warning past a stated limit. Every review MUST leave a run list of its agent runs, each with its tokens, the cost its run log reported and why it was not accepted, and a run report built from it on which every string an agent's
