## 5.10 Observability (OPS)

| ID     | Pri | Requirement                                                                                                                                                                                                 | Ver | Traces |
| ------ | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------ |
| OPS-01 | P0  | Every failed, dropped, rejected, redacted, timed-out, truncated or coalesced operation MUST append an entry to the audit log and increment a named counter derived from it.                                 | T   | I6     |
| OPS-02 | P0  | The audit log MUST be append-only JSONL with its own hash chain, created `0600`, rotated with chain continuation.                                                                                           | T   | I6     |
| OPS-03 | P0  | `parinn doctor` MUST exit non-zero while any failure counter has increased since the node's principal last acknowledged them (`parinn counter ack`).                                                        | T   | I6     |
| OPS-04 | P1  | ParleyInn SHOULD provide `parinn canary`, which writes a canary event through capture's ingest path (REC-13), recalls it through MCP and exits non-zero on failure.                                         | T   | I6     |
| OPS-05 | P1  | ParleyInn SHOULD emit structured logs (JSON) to a file or stderr, but a hook handler MUST log only to the home's log file and write nothing to stderr (§9.1). ParleyInn itself MUST NOT ship logs anywhere. | T   | I2, I4 |
| OPS-06 | P1  | Every B1–B3 component MUST append every operation OPS-01 names to the home's audit log and increment its named counter. No failure MAY be visible only in a browser.                                        | T   | I6     |
