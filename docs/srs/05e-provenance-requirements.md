A key event MUST carry only its kind, the key's fingerprint, the digest of its recovery key's public key, the digest of the key event it follows, the fingerprint of each key it replaces and its signatures; a rotation also its recovery key's public key; a rotation, a `minted anew` and a `revoked` also, per key event log it continues, replaces or revokes in, the chain head of the device seat writer that recorded that key event log's newest key event; a `recovered` the digest of the newest key event of the key event log it joins; a `token key adopted` its token certificate, scoped to this node's personal room and naming the token key it succeeds, if any (PEER-06). The genesis log's inception is the first event of the device seat that created the personal room; a `minted` or `token key adopted` following a node identity change event in its writer replaces the key that event names; a `minted anew` replaces the missing device key it names, or, named by a backup restore's principal act, every earlier key event log (ADM-06). A rotation (`rotated`, `recovered`) MUST be signed by the recovery key the key event it follows committed to and name as the new key one freshly minted, never the recovery key; a `rotated` MUST also be signed by the key it replaces; a `recovered` MUST name a `minted anew` that replaced its key event log's newest key, joining that inception's key event log to its own, after which no rotation the joined inception's recovery key signs counts. A `revoked` MUST be signed by the revoked key, its committed recovery key or, once PRV-10 ships, the principal key certifying it. A reject, a cut principal act, voids an inception no confirm or `recovered` has counted, voids a node identity change event the key it replaces signs it for, and acknowledges a named void key event. Two newest key events of one key event log, two counting inceptions replacing one key, or two node identity change events leaving one key event log, are a duplicity: no key of a key event following it MAY certify a `witnessed` writer until a choose names the key event to keep or a reject or rotation voids the other. A token key's recovery key MUST be minted and kept by the node that issued its access token, the access token carrying only its digest, and erased there once the expire act ending that access token is recorded or it is revoked; a later access token (`parinn access-token rotate`) carries the rotation that node signed, never the recovery key. Before a confirm, choose, reject or `recovered` takes effect, ParleyInn MUST show the device seat that recorded each inception it concerns, whether the key that inception replaces is still in the key store, each certificate record after its chain head and each pin that would start or stop restoring, with its text escaped; a `recovered` MUST name its `minted anew` by digest and is refused while more than one waits.
