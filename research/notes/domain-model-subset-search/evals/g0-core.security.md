I reviewed candidate.md for g0-core through the security lens and edited no file. Every quote below appears exactly once in candidate.md (checked with grep -cF).

There are 9 needs-fix findings. They fall into three groups:

- **The agent can pass for the person, the harness or the principal's device seat.** It runs `parinn` as the same OS user, and the only test the candidate gives is "at a terminal" / "output is not a terminal". That opens four holes: widening principal acts, unenveloped CLI recall, trusted `operator` room acts, and forged `parinn hook` calls. Configuration the agent can edit and that nobody has accepted adds a fifth.
- **Trust rules that are inconsistent or missing.**
  - A device-seat pin restores to "its author's principal's agents", but I2 and I8 trust only this node's own events. Node clone (the only multi-node path in the candidate) brings this into play.
  - What seat-key revocation does to earlier events is never stated.
  - A subagent's delegated task can become a trusted `user` event.
- **Boundaries.** B1 and B3 are named, but I4 declares only B0.
