### SRS and scenario defects (needs-fix)

1. **OWN-28 gives "correction" two meanings.** At 05c-principal-and-peer-requirements.md:44, "each correction a principal act" covers three acts: send a correction, revise the intent, and retry. The model's Correction is only the principal-typed text in a fixed template. Fix: "each a principal act naming the verdict it answers".
2. **OQ-14 uses "delegation" for a principal handing authority to another principal.** At 13-open-questions-and-risks.md:25, "Default: no delegation" means that, but Delegation is one agent handing another a delegated task. The same row then uses the right sense for OWN-26. Fix: "Default: only the agent's own principal instructs it (OWN-01)".
3. **The PRV-02 scenario title says "unsigned trusted sources".** At features/provenance.feature:37, "unsigned" belongs to record.md: events after the newest seal. These sources are sealed. Fix: "this node's own trusted sources". "Unsigned" belongs to the record specialist.
4. **§11.1 uses "recall" in its statistics sense.** At 11-verification-and-acceptance.md:26, "Precision ≥ 0.9†; recall reported" is a classifier metric, not a call to a recall tool. Fix: "share of malicious items flagged reported".
5. **OWN-26's I2-review gate has drifted** (not a naming issue, but it gates the acceptance grant). OWN-26 (05c:42) says it must pass a recorded I2 security review under ENG-29. ENG-29 (10-engineering-quality.md:59) names only PRV-10 and PRV-11. The OWN-26 scenario (principal-acts.feature:309-319) lacks the review step that the PRV-10 and PRV-11 scenarios carry. Fix: add OWN-26 to ENG-29's list and add the step to the scenario.

### SRS contradictions on this file's concepts (questions)

6. **A settings key can change the default recall scope, which RCL-05 forbids.**

  - RCL-05 (05-functional-requirements.md:82) says recall must default to `run`, and extending it must take an explicit `scope` parameter.
  - Yet §9.6 (09-interfaces.md:182) ships `recall.default_scope`, settable to other values in the principal's configuration. ADM-04 (05a:17) and SEC-11 (06-security.md:101) treat loosening or extending it there as allowed, and security.feature:144 tests `rooms`.
  - Either remove the key (or pin it to `run`), or let RCL-05 allow a configured default.

7. **OWN-22 and §9.7.6 disagree on where risk acceptance shows.** OWN-22 (05c:38; principal-acts.feature:269) says the risk acceptance must be shown on every surface beside each run that relies on it. §9.7.6 (09b-lane-vocabulary.md:136-137) says "Unsandboxed agents are one line on Health, not a mark on every tile."
8. **Some recall tools reach beyond the run with no `scope` parameter.** `room_get` with `id`, `pin_list` with `room` and `room_summary_get` (09-interfaces.md:50, 56, 74) return room content beyond the current run. RCL-05 requires an explicit `scope` parameter and logging for that. Do these tools fall under RCL-05?

### Gaps in trust-and-flow.md itself (questions, since the file is not under change)

9. **Counter** (lines 140-141) says counters are "shown on Health until acknowledged". ADM-11 (05a:24) and §9.5 `parinn status` (09a:16) keep non-zero counters shown. OPS-03 uses acknowledgement only as `parinn doctor`'s baseline.
10. **Continuation cursor** (lines 52-54) says "A recall tool that stops at its per-call cap returns a continuation cursor". `kernel_exec`, which the model calls a recall tool, returns a truncation marker instead (CMP-06; record.md:148-149). `landmark_list` has a cap but no cursor. RCL-03 (05-functional:80) also lacks "without gap or overlap", which only its scenario (recall.feature:48) asserts.
11. **Focus set** (lines 159-160) says its rooms "come first in Needs you". §9.7.4 (09b:88-90) puts them first only inside Q2 and Q3, after class order.
12. **Sandbox state** (lines 117-119) includes "its policy digest". OWN-22 and the rest of the SRS never require one.
13. **Quota** (lines 108-110) says it is set by "the node's principal or managed policy". §9.6 (09-interfaces:183) also lets repository configuration lower `quota.*`.
14. **Petname** (lines 176-178) says "never one another principal sent". VIEW-07 (05b-room-view:44) says "never a name another principal or a peer sent".
15. **Front-matter summary** (line 5, and the hub catalog row generated from it) lists "the Needs you queue". That concept is defined in components-and-surfaces.md; this file defines only queue classes and the focus set.
