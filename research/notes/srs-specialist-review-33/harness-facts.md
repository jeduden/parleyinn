## Harness facts: round 33 standing review of `docs/srs/` and `features/*.feature` against `harness-facts.md`

I found 9 defects, all checked on disk: 3 SRS wordings that need fixing, 5 questions for the stakeholder, and 1 for another specialist. The worst is that I2 is looser about compaction guidance than every other place that defines it; fixing that needs new invariant wording. No finding touches OQ-39, OQ-40 or OQ-41.

**What is clean:**

- No bare "session", "project" or "import of a transcript" appears. Every use is "harness session", a harness's own name (`SessionStart`, `session_id`, `allow-session`, `~/.claude/projects`), or an outside project's name in an evidence column.
- "Transcript source", "transcript generation", "transcript roots", "hook input", "user turn", "turn trigger" and "compaction guidance" carry the model's meaning everywhere they appear.
- No other model file defines any of my bold terms again.
- The hub relation "Ingest splits one transcript by run" agrees with REC-02.
- The cited ids ASM-03, REC-01, REC-07, SEC-18, PRV-02, PIN-07, NG1, I3 and I7 say what my file says they say. The LANE-14 citation is the exception (finding 5).

### Findings

1. **Hook output is used but never defined (question, my file).** The model defines **hook input** but has no name for what a hook handler returns. "Hook output" still carries I2-relevant rules in OWN-03, OWN-04, VIEW-17, §6.3 row 6 and §4.2, and in the restore, principal-acts, lane-view, engineering, lane and assumptions scenarios. Fix: add **hook output** to the Hook entry.

2. **"Hook event" uses "event" in the harness's sense (question).** In the model, an event is only an entry in a writer. LANE-02 ("at the first hook event"), lane.feature:37 and 39, and assumptions.feature:156 use it for a hook firing; ASM-17's "the event" is the same pattern. The stakeholder should rule whether this is the harness's own name, allowed by the hub's rule for outside things, or should become "the first hook" / "each hook fired". The model's own copy, git-and-forge.md:12, belongs to the git-and-forge specialist.

3. **Turn does not say whether the tool loop is one turn (question, my file).** Read literally, "one exchange … from an input to the model reply that ends it" makes every tool result an input, and so a turn trigger. LANE-14's "Nothing else MAY trigger a turn" forbids that. OWN-15's "mid-turn steer", §9.7.1 Working/Idle and the restore block's "turns 31–33 · Edit×6 Bash×4" all assume one turn spans the loop.

4. **LANE-14 cannot be met for a subagent (needs-fix, SRS).** It lists the trigger as "a delegation and its delegation grant", but a subagent has no grant (OWN-23). OWN-24 already says "when one applies"; LANE-14 should too.

5. **LANE-14 is cited for `harness_text`, which it does not say (question for my file, needs-fix for §9.7.6).** LANE-14 says only "mark untrusted"; PRV-08 is what makes the line `harness_text`. The same mis-citation is in §9.7.6.

6. **PIN-07's condition points at the wrong assumptions (needs-fix, SRS).** PIN-07 is gated on "ASM-01/02", but neither assumption nor the ASM-02 scenario covers `PreCompact` output. ASM-02's Affects column lists only INJ-*. The real open question is OQ-02, answered in spike S1.

7. **I2 lets compaction guidance carry ids and structural fields (question, needs new I2 wording).** I2 says compaction guidance is built from "fixed text ParleyInn ships, trusted structural fields and ids". PIN-07, §9.1, §4.4 and my file all say fixed text only, never record content, and the change log records that as the decision. Tightening I2 needs an ADR and a security review.

8. **LANE-28 and its scenario trace I7, which does not cover the commit hook (question).** I7 protects harness configuration. My file says git's hooks are always qualified, and the commit hook is not harness configuration. The smallest fix is to drop I7 from LANE-28, its scenario tag and Appendix B. The alternative is new I7 wording.

9. **§6.3 row 24 leaves out recalled content (other specialist: components-and-surfaces).** The row says the harness's model traffic carries only "what I2's closed paths write". I4 also names recalled content an agent receives through a tool call.

### Instruction feedback

- The hub's rule that "an outside thing keeps its own name when its domain qualifies it" gives harness examples only for "session". The instructions don't say whether other harness-native words, such as "hook event" or "hook output", fall under that rule or need a model entry, so findings 1 and 2 had to be questions rather than verdicts.
- The instructions don't say whether a requirement's invariant trace (its Traces column, scenario tags and Appendix B) is in scope when the trace stretches an invariant my file serves (finding 8). I treated it as in scope.
- They also don't say whether wrong or misdirected assumption gates (ASM rows, spikes, OQs) on a concept I own are in scope (finding 6). I included it.
