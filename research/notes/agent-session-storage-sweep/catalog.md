# Agent session storage catalog

This catalog covers systems that store, share, attribute or replicate the
history of AI coding-agent sessions, plus the log, sync and provenance
infrastructure such systems are built on. Candidates came from 8 discovery
modalities: session capture, agent memory, orchestration, hosted platforms,
provenance and attribution, version control, logs and sync engines, and
community listings. Haiku agents then ran size and activity checks on 197
candidates. Each surviving system got a deep read against primary sources
(docs, source at a pinned commit, changelogs), recorded as a fact sheet with
fixed fields. Two completeness critics then looked for missing systems and
missing angles, and their finds went through the same triage and deep read.
That produced 325 fact sheets, which merge to 308 distinct systems once 17
duplicates are removed. 77 candidates were not deep-read: 56 as small or
inactive, 21 as off-topic. Five of those 77 were deep-read anyway under
another name (Willow, Keyhive and Beelay, Zep through Graphiti, Sapling,
Oxen). Orca (stablyai/orca) was deep-read against the same fields on
5 October 2026, after the sweep, and brings the catalog to 309 systems.
The per-system tables below this overview are generated from the sheets;
this overview is the synthesis.

## Storage patterns

Each system was given one primary pattern, judged by hand from its "where
stored" field. Many systems use two places (a local SQLite plus a hosted
mirror, or git notes plus a hosted transcript store), so the counts show the
place that holds the authoritative copy and are approximate. Generic
infrastructure (Dolt, Fossil, Sapling) was put where its data lives on disk.

| Pattern                                | Count | Examples                                                        |
| -------------------------------------- | ----- | --------------------------------------------------------------- |
| Working-tree files in the code repo    | 22    | Aider, SpecStory, ctxmem, Backlog.md, Serena memories           |
| Git notes                              | 12    | Agent Note, AgentBlame, git-memento, whogitit, SLSA source-tool |
| Custom refs or orphan branch           | 11    | Entire CLI, Rekal, oobo, gittuf, Gerrit NoteDb                  |
| Separate git repo (incl. shadow repos) | 23    | claude-code-sync, gitmemory, Letta, Cline checkpoints, clync    |
| Local DB or files outside the repo     | 90    | Claude Agent SDK sessions, Copilot CLI, cass, lcm, agentsview   |
| Hosted server or DB                    | 90    | Copilot cloud agent, Devin, Cursor Cloud Agents, kcap, Langfuse |
| P2P or append-only log                 | 24    | Hypercore, Autobase, C2SP tlog-tiles, S2, Durable Streams       |
| CRDT or op-log                         | 13    | Automerge, Loro, Jujutsu op log, Zed Delta, LiveStore           |
| None of these (specs, policies, libs)  | 24    | ACP, Agent Trace, Linux kernel Assisted-by, in-toto predicates  |

Two counts stand out. Local stores and hosted stores together hold 180 of
309 systems. GitHub and GitLab, the two vendors that own both an agent and
a forge, keep agent transcripts on their servers rather than in git. The
git-resident patterns (working tree, notes, refs, separate repo) hold 68
systems, and they account for most of the documented silent data loss in
the catalog.

## Cross-cutting findings

### Verbatim transcripts

Full verbatim transcripts are common, but almost never in the code repo's
shared history. The cases split four ways.

- **Agent-native local logs.** Claude Code, Codex, Copilot CLI, Pi, goose,
  Gemini CLI and OpenHands all keep a per-session append-only log on local
  disk. Copilot CLI's per-session `events.jsonl` is the source of truth and
  its SQLite store is explicitly rebuildable
  ([Copilot CLI chronicle](https://docs.github.com/en/copilot/how-tos/copilot-cli/chronicle)).
  OpenHands writes one immutable file per event plus a mutable head pointer
  ([OpenHands EventLog](https://docs.openhands.dev/sdk/arch/conversation.md)).
  These logs are not durable records. Claude Code deletes transcripts after
  30 days by default
  ([claude-code-log](https://github.com/daaain/claude-code-log)), streaming
  writes several entries per `message.id`, and resumed sessions copy prior
  messages into new files ([Sniffly](https://github.com/chiphuyen/sniffly)).
- **Local archives built on top.** lcm, lossless-claw, episodic-memory,
  MemPalace and cass copy native logs into their own store. Their "lossless"
  claims fail at ingest more often than in storage: lossless-code keeps only
  text blocks and drops tool use, tool results and thinking
  ([lossless-code](https://github.com/GodsBoy/lossless-code)).
- **Git-resident transcripts.** git-memento stores full transcripts verbatim
  in a notes ref with no redaction
  ([git-memento](https://github.com/mandel-macaque/memento)). Entire keeps
  them on sharded checkpoint refs behind six redaction layers
  ([Entire CLI](https://github.com/entireio/cli)). claude-code-sync, clync,
  claude-nomad, ai-session and gitmemory put them in a separate repo, and
  Aider and SpecStory put them in the working tree.
- **Hosted transcripts.** Claude Code cloud sessions, the Copilot cloud
  agent, Cursor Cloud Agents, Devin, Codex cloud, Jules and Warp keep the
  transcript on the vendor's servers and put only a URL or trailer in git.
  Hugging Face ran this exact workload, raw Claude Code JSONL from many
  machines, and its docs say git "is not meant to work as a database with a
  lot of writes"
  ([HF Agent Traces](https://huggingface.co/docs/hub/en/agent-traces)).

### Real time

No git-based system in the catalog is real time. Every one syncs on commit,
push, a hook or a manual command. Real time comes from four other shapes.

- **Hosted relays.** Happy relays end-to-end encrypted session traffic over
  Socket.IO, with the server seeing only ciphertext
  ([Happy](https://github.com/slopus/happy)). C3Sync pushes sealed events
  through a self-hosted NATS JetStream hub ([C3Sync](https://getc3.app/sync)).
  Nimbalyst runs one encrypted stream per session
  ([Nimbalyst](https://github.com/Nimbalyst/nimbalyst)). kcap tails the
  agent's own transcript file and streams it over SignalR
  ([kcap](https://www.kurrent.io/how-it-works/)). Claude Code Remote Control
  mirrors a local session through Anthropic's servers
  ([Remote Control](https://code.claude.com/docs/en/remote-control)).
- **Append-only stream servers.** Durable Streams, S2 and NATS JetStream give
  offset-addressed appends with long-poll or SSE tailing and idempotent
  producers ([Durable Streams](https://github.com/durable-streams/durable-streams),
  [S2](https://s2.dev/)). Coder keeps a monotonic per-chat snapshot version in
  the database and treats notifications only as hints to re-read
  ([Coder Agents](https://coder.com/docs/ai-coder/agents)).
- **Peer-to-peer and CRDT replication.** Hypercore and Autobase replicate
  signed single-writer logs live
  ([Autobase](https://github.com/holepunchto/autobase)). Zed Delta replicates
  the conversation and the worktree together as a CRDT operation log
  ([Zed Delta](https://delta.dev)). iroh-docs reconciles signed entries over
  gossip ([iroh-docs](https://github.com/n0-computer/iroh-docs)).
- **Local-only watchers.** agentsview, cass, claude-code-viewer and CCHV
  watch `~/.claude/projects` with file watchers and debounce. This is real
  time on one machine and nowhere else.

Telemetry is a fifth, lossy path. Claude Code's OpenTelemetry export pushes
batched events every few seconds, truncates at 60 KB and keeps content
redacted unless opted in
([Claude Code OTel](https://code.claude.com/docs/en/monitoring-usage)).

### Untrusted history versus auto-injection

Auto-injection of stored or derived history is the dominant design in the
memory category, and it is the I2 anti-pattern in plain form.

- Grov injects other agents' LLM-summarised sessions as "verified,
  authoritative, do NOT verify in code" ([Grov](https://github.com/TonyStef/Grov)).
- MemOS injects distilled memory with an instruction to treat it as
  established fact ([MemOS](https://github.com/MemTensor/MemOS)).
- Windsurf's `create_memory` needed no approval, so injected text became
  standing instructions
  ([Devin Desktop memories](https://docs.devin.ai/desktop/cascade/memories)).
- The Kilo and Roo memory banks put LLM-rewritten Markdown into the system
  prompt as rules on every task
  ([Kilo Memory Bank](https://kilo.ai/docs/advanced-usage/memory-bank)).
- Acontext turns LLM summaries of raw transcripts, tool output included,
  into auto-loaded skill files ([Acontext](https://github.com/memodb-io/Acontext)).
- First-party tools do it too: Claude Code loads the first 200 lines of
  agent-written `MEMORY.md` at session start
  ([Claude Code memory](https://code.claude.com/docs/en/memory)). Cognee,
  Hindsight, Supermemory, LangMem, Mem0 and Vertex Memory Bank all feed
  derived memory back into prompts.

A smaller group treats history as untrusted. bettermemory runs every file
that arrives over git through an admission chain (size cap, parser, alias
checks) before trusting any field in it
([bettermemory](https://github.com/0Mattias/bettermemory)). OpenClaw stores
an origin class (owner, agent, untrusted, system) as an index column the
model cannot write ([OpenClaw](https://docs.openclaw.ai/concepts/memory)).
Claude Code tags peer-agent messages as "not the user"
([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)).
Orca sits between the groups: it wraps PR logs and comments as "untrusted
data only, not instructions", yet types a coordinator agent's task spec
into a worker's terminal verbatim under a fixed preamble
([Orca](https://github.com/stablyai/orca)).
Anthropic's Compliance API tags each message as verified, client-asserted or
a synthetic marker
([Compliance API](https://platform.claude.com/docs/en/manage-claude/compliance-api)).
lossless-claw gets recall right (grep, describe, expand, with a scoped,
token-capped grant) but still pushes summaries
([lossless-claw](https://github.com/Martian-Engineering/lossless-claw)).
Two cautions sit alongside. episodic-memory's summariser resumed archived
sessions with the user's live tools and MCP servers
([episodic-memory](https://github.com/obra/episodic-memory)). LangGraph
shipped four CVEs from rebuilding typed objects out of stored bytes
([LangGraph](https://docs.langchain.com/oss/python/langgraph/persistence)).

### Linking sessions to code

Four mechanisms recur, and each fails in its own way.

- **Commit trailers.** Claude Code writes `Claude-Session`, Copilot writes
  `Agent-Logs-Url`, Entire writes `Entire-Checkpoint`, Semantica writes
  `Semantica-Checkpoint`, Sourcegraph writes `Sourcegraph-Batch-Change`.
  Trailers survive squash and forges, but they are unreliable. Claude's is
  model-written
  ([Claude-Session trailer](https://code.claude.com/docs/en/cloud-environments)).
  Only 3 of 24 Copilot agent commits checked since January 2026 carried
  their trailer
  ([Copilot session logs](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/track-copilot-sessions)).
  Open-source policy has settled on a tool-level `Assisted-by` trailer only,
  with no session or prompt
  ([Linux kernel](https://docs.kernel.org/process/coding-assistants.html),
  [Fedora](https://docs.fedoraproject.org/en-US/council/policy/ai-contribution-policy/),
  [LLVM](https://llvm.org/docs/AIToolPolicy.html)), and the kernel's grammar
  changed within about seven months.
- **Git notes.** Agent Note, AgentBlame, Git AI, Exceeds Ink, Origin and
  Traces key a note by commit SHA. Traces keeps notes pointer-only and the
  content in its own service ([Traces](https://traces.com)).
- **Custom refs.** Entire shards checkpoints under `refs/entire/checkpoints`,
  Rekal gives each author an orphan branch
  ([Rekal](https://github.com/rekal-dev/rekal-cli)), and oobo writes an
  id-derived tree on an orphan branch through a CAS loop
  ([oobo](https://github.com/ooboai/oobo)).
- **IDs and hashes held outside git.** Devin, Cursor and Codex cloud link by
  PR URL on their side. Kilo, OpenCode and Gemini CLI store snapshot tree
  hashes inside the session record
  ([Kilo checkpoints](https://kilo.ai/docs/features/checkpoints)). Diversion
  mints a checkpoint id in PreToolUse just before a commit
  ([Diversion](https://www.diversion.dev/diversion-claude-code-plugin)).

A fifth approach derives links after the fact. ctx blames commits, line
ranges and PRs from evidence the record already holds and abstains with a
typed reason when proof is incomplete ([ctx](https://github.com/ctxrs/ctx)).
Lore uses a tiered matcher from an exact SHA anchor down
([Lore](https://github.com/tt-a1i/lore)). The cost of not recording at write
time shows in Claude Code's contribution metrics, which fuzzy-match
normalized lines inside a 21-day window
([contribution metrics](https://code.claude.com/docs/en/analytics)), and in
Gitify Prompt, which guesses the session by timing
([Gitify Prompt](https://github.com/gauravkrp/git-for-prompts)).

### Privacy and redaction

Redaction practice runs from strong to absent, and the defaults matter more
than the features.

- **At capture, always on.** Entire layers entropy scoring, Betterleaks
  patterns and provider rules. cass redacts by default with 13 regex
  families ([cass](https://github.com/Dicklesworthstone/coding_agent_session_search)).
  Rekal and lcm redact before the first write, and oobo puts everything
  through one publish gate.
- **At export, fail closed.** pi-share-hf redacts exact literal values and
  gates the upload ([pi-share-hf](https://github.com/badlogic/pi-share-hf)).
  Opaline runs 18 gitleaks-derived rules on the client
  ([Opaline](https://github.com/opalinehq/cli)).
- **Gated on the wrong step.** claude-nomad scans inside `nomad push`, so a
  plain `git push` skips the scan
  ([claude-nomad](https://github.com/funkadelic/claude-nomad)).
  claude-context-sync's automatic mode silently falls back to plaintext
  ([claude-context-sync](https://github.com/Daniel-de-Oliveira-Trindade/claude-context-sync)).
  claude-session-management promises a sanitiser it never calls.
- **None.** git-memento, agentdiff, ai-blame and gitmemory store prompts
  unredacted. AgentBlame stores verbatim prompts in notes by default
  ([AgentBlame](https://github.com/mesa-dot-dev/agentblame)). OpenCode
  shares are public, last-write-wins snapshots that cannot be recalled
  ([OpenCode /share](https://opencode.ai/docs/share/)).
- **Hash, do not store.** OpenFab hashes the prompt and keeps it out of the
  signed artefact ([OpenFab](https://github.com/Open-fab-ai/openfab)), and
  agentattest stores no raw prompts by default.

Sync-on-by-default is the most common privacy gap among vendors: Copilot CLI
syncs local sessions to the GitHub account unless turned off
([Copilot CLI](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-copilot-cli)),
and Factory mirrors to its cloud by default
([Factory](https://docs.factory.com/docs/droid-cli/settings)).

### Recurring failure modes

- **Shared mutable notes refs.** gitwhy and whogitit overwrite with
  `notes add -f` ([gitwhy](https://github.com/surajsrivastav/gitwhy)). A
  forced fetch refspec destroyed CommitLore's unpublished records
  ([CommitLore](https://github.com/MongLong0214/commitlore)). Git Prompt Story
  force-pushes a parentless tree ref
  ([Git Prompt Story](https://github.com/QuesmaOrg/git-prompt-story)), and a
  wildcard push sent memento's private transcripts to the remote.
- **CAS without recompute.** agentdiff retries a non-force ref update without
  rebuilding the content, so concurrent writers lose records silently
  ([agentdiff](https://github.com/codeprakhar25/agentdiff)).
- **Two writers on one chain.** Two NTM processes appended the same sequence
  number with the same previous hash, which left verification permanently
  red ([NTM](https://github.com/Dicklesworthstone/ntm)).
- **Whole-file last-writer-wins.** The MCP reference memory server, the
  Claude memory tool and claude-sync all lose concurrent updates
  ([MCP reference memory](https://github.com/modelcontextprotocol/servers/tree/main/src/memory)).
- **Counter-based ids.** goose allocates `YYYYMMDD_N` from a local counter,
  so import across machines must renumber
  ([goose](https://goose-docs.ai/docs/guides/sessions/session-management));
  Task Master's answer to merge conflicts is to renumber task ids.
- **Size blowups.** Raw-tracking `~/.claude/projects` caused a host OOM and
  a dead mirror for syncestra
  ([syncestra](https://pypi.org/project/syncestra/)).
- **Capture tied to runtime internals.** claude-trace stopped working when
  Claude Code moved to a Bun binary
  ([claude-trace](https://github.com/badlogic/lemmy/tree/main/apps/claude-trace)).
- **Vendor death.** Terragon's session record died with its hosted service
  ([Terragon](https://github.com/terragon-labs/terragon-oss)). Vibe Kanban's
  cloud closed 30 days after the announcement, while its local SQLite record
  kept working ([Vibe Kanban](https://github.com/BloopAI/vibe-kanban)).
- **Hash preimage bugs.** Oak's newline-joined BLAKE3 input caused three
  integrity bugs in under six months ([Oak](https://oak.space)).
- **Branches as security boundaries.** DiffMem isolates tenants as orphan
  branches in one repo, which any read-only git command crosses
  ([DiffMem](https://github.com/Growth-Kinetics/DiffMem)).

### Against the earlier digest

The earlier `research/reports/interesting-ideas-digest.md` drew on about
175 systems. The larger sweep confirms its main points and
adjusts a few.

- **Confirmed.** Git holds the pointer, not the live record. One writer per
  log. Redact at capture. Every pull is untrusted. The sweep adds more
  vendors that keep the transcript off git (Sourcegraph Agentic Batch
  Changes, Replit, Jules, Warp, Augment Cosmos, Coder) and one more move
  away from git for raw history: GrayCodeAI/trace dropped its orphan-branch
  design. It found no documented move the other way.
- **Sharpened.** The trailer case is weaker than the digest said: open-source
  policy (kernel, Fedora, LLVM, OpenInfra, ASF) now standardises a
  tool-level trailer that names no session at all.
- **Changed.** The digest framed git as unfit for history. gittuf, SLSA
  source-tool and Tangled show that signed, hash-chained records in a custom
  ref cross unmodified forges well when volume is low
  ([gittuf](https://github.com/gittuf/gittuf),
  [SLSA source-tool](https://github.com/slsa-framework/source-tool)). The
  limit is write rate and shared mutability, not git itself.
- **New.** Vendor shutdown is now a documented failure mode (Terragon, Vibe
  Kanban, Roo Code Cloud). Provenance classes from the Compliance API, and
  the in-toto agent predicates, are new prior art for trust labels and
  signed export. The memory category's auto-injection habit is wider than
  the digest showed: about a dozen systems, first-party ones included.
- **Counts.** Hosted and local stores came out larger than the digest's
  keyword counts (about 90 each here, against about 75 and 80 for local
  databases plus local files), mostly because the sweep added hosted
  platforms, viewers and orchestrators.

## Lessons for ParleyInn

1. **Ingest native transcripts as untrusted, mutable input; never adopt them
   as the record.** Claude Code deletes them after 30 days, CCHV rewrites
   them in place while Claude appends, and Sniffly shows duplicate entries
   per message. Take whole lines up to a watermark, as Opaline does, and tie
   each chunk to a byte range of the source, as gitmemory does
   ([gitmemory](https://github.com/doronp/gitmemory)). Quarantine a source
   that shrank or was rewritten. Sources: claude-code-log, CCHV, Sniffly,
   Opaline, gitmemory. Invariants: I1, I6.
2. **Decide losslessness at the ingest boundary and count every skip.**
   Capture every block type, including tool use, tool results and thinking,
   and audit anything dropped. Do not capture by patching the client's
   runtime. Sources: lossless-code, claude-trace, Claude Code checkpointing
   ([checkpointing](https://code.claude.com/docs/en/checkpointing)), whose
   file history is tool-scoped. Invariants: I1, I6.
3. **One writer per chain, and the writer is the process.** Give each
   process, sandbox or machine its own chain and merge only at read time
   into a rebuildable index. Sources: NTM, agentsview
   ([agentsview](https://github.com/kenn-io/agentsview)), Rekal, Autobase,
   C2SP. Invariants: I1, I10.
4. **Never share a mutable ref, file or notes tree between writers.** If
   ParleyInn ever uses git refs as transport, write immutable, uniquely named
   objects, never force a refspec, and never push a wildcard namespace.
   Sources: gitwhy, whogitit
   ([whogitit](https://crates.io/crates/whogitit)), CommitLore, Git Prompt
   Story, agentdiff, git-memento, container-use. Invariants: I1, I6.
5. **Recall stays pull-only, and the trust class is a column set by the
   capture path.** The model must never write it, and it must be enforced
   again at every recall. The counter-examples are Grov, MemOS, Windsurf,
   the Kilo and Roo memory banks and Acontext. The positive cases are
   OpenClaw, Claude Code's "not the user" peer label and the Compliance
   API's provenance classes. Invariant: I2.
6. **Anything that reads stored history runs with zero authority and treats
   bytes as data.** Summarisers, indexers and exporters get no tools, no MCP
   servers and no live config. Stored bytes are never deserialised into
   executable or typed objects. Sources: episodic-memory, LangGraph, Goose
   (which retired Nostr sharing within about 4.5 months,
   [Goose export](https://www.mankier.com/1/goose-session-export)).
   Invariant: I2.
7. **Redact at capture, record each redaction, and make export a separate
   fail-closed step.** A gate on a transport command is skipped by the plain
   command, and an opt-in flag the hooks never pass protects nobody.
   Sources: Entire, cass, Rekal, lcm, pi-share-hf against claude-nomad,
   claude-context-sync and claude-session-management. Invariants: I1 (the
   recorded redaction exception), I6.
8. **If ParleyInn touches git at all, it writes a hook-generated pointer to a
   record hash, and only on explicit opt-in.** Trailers written by models
   go missing, forges and maintainers rewrite them, and policy grammars
   change. The record must hold the session-to-commit link on its own.
   Sources: Claude-Session, Copilot's Agent-Logs-Url, Linux kernel and
   Fedora policy, Semantica ([Semantica](https://github.com/semanticash/cli)),
   VS Code's co-author trailer. Invariants: I6, I7.
9. **Session-to-code attribution is a derived index with typed abstention.**
   Build it from SHAs and patches already in the transcript, and say "not
   proven" rather than match on timing. Sources: ctx, Lore, ai-blame
   ([ai-blame](https://github.com/ai4curation/ai-blame)) against Claude Code
   contribution metrics and Gitify Prompt. Invariant: I10.
10. **Anchor code state as tree hashes in an out-of-tree object store, and
    pin them.** A shadow git dir driven with `--git-dir` and `--work-tree`
    gives cheap per-step snapshots without touching the user's refs. Sources:
    Kilo, OpenCode ([OpenCode snapshots](https://opencode.ai/v2/docs/snapshots/)),
    Gemini CLI checkpointing, Roo Code. Invariants: I1, I8.
11. **The local record must outlive every vendor and every share link.**
    Warp shares expire after about a week, GitLab deletes sessions 30 days
    after last activity, and Terragon's record died with its service.
    Sources: Terragon, Vibe Kanban, Warp
    ([Warp shares](https://docs.warp.dev/guides/agent-workflows/how-to-attach-agent-session-context-to-github-prs/)),
    GitLab Duo
    ([GitLab sessions](https://docs.gitlab.com/user/duo_agent_platform/sessions/)).
    Invariants: I1, I4.
12. **Real-time sharing lives outside the core as a relay of sealed,
    encrypted, idempotent appends.** Each append states where it lands,
    duplicates count as success, gaps are refused, and notifications are only
    hints. Sources: Happy, C3Sync, Nimbalyst, Durable Streams, S2, Coder,
    and Remote Control as the case where the mirror is not authoritative.
    Invariants: I4, I9.
13. **Chain commitments, keep payloads apart, and add a Merkle layer.**
    Hashing payloads into a separate value log lets a purge or redaction
    delete bytes while every proof still verifies, and tiles give inclusion
    and consistency proofs a linear chain cannot. Sources: immudb
    ([immudb](https://github.com/codenotary/immudb)), Trillian, C2SP
    tlog-tiles, torchwood
    ([torchwood](https://pkg.go.dev/filippo.io/torchwood)). Invariants: I1,
    I5.
14. **Fix canonical bytes before the first record ships.** Use a
    length-prefixed or JCS-style encoding, store exactly those bytes, and
    have the verifier recompute and reject on mismatch. Sources: Oak, the
    in-toto AI Agent Action predicate
    ([in-toto PR 588](https://github.com/in-toto/attestation/pull/588)).
    Invariants: I10, I6.
15. **Forks get deterministic ids and are never merged.** Only a strict
    prefix merges automatically. A fork's id is derived from the parent
    chain and the first differing event, so every machine names it the same
    way. Compaction and rewind append entries rather than rewrite. Sources:
    agent-sync ([agent-sync](https://github.com/lidongpeng36/agent-sync)),
    Factory, Pi ([Pi sessions](https://pi.dev/docs/latest/tree)), OpenHands.
    Invariants: I1, I3, I10.

## Gaps and low-confidence entries

**Low confidence and unverifiable.** One entry is low confidence with status
unverifiable: AGENTS.md, whose claimed Linux Foundation stewardship could
not be confirmed and whose sheet holds no usable facts
([AGENTS.md](https://openai.com/index/agentic-ai-foundation/)). 29 entries
are medium or medium-high. The ones whose gaps bear on ParleyInn's questions:

- Where the transcript lives and for how long, for hosted platforms whose
  backends are undocumented: Devin, Factory, Replit, Lovable, GitLab Duo,
  Junie, Rovo Dev, the Copilot coding agent, and third-party agents in
  GitHub Agent HQ.
- Vendor-only sources with no independent check: Mesa, Exceeds Ink,
  Diversion, Git AI.
- Lineage or availability problems: GrayCodeAI/trace (two unrelated
  codebases under one name), whogitit (repository returns 404; facts from
  crates.io), GitButler's removed hooks.
- Proposals, not shipped: the in-toto agent-decision RFC, Keyhive and
  Beelay, and the OpenSSF TAC proposal.

Several sheets note that their web search budget ran out (Mesa, the Copilot
coding agent), so third-party discussion was not checked.

**The 20 critic angles, condensed.**

1. Non-Claude on-disk formats and resume semantics (Codex, Gemini CLI,
   Cline, Aider, Cursor, Windsurf, Copilot CLI, OpenCode, Goose).
2. How notes and ref layouts (Gerrit NoteDb, git-bug, Radicle, Entire,
   Beads) survive rebase, force-push, GC and forge ref limits.
3. ParleyInn as a backend for existing session interfaces (Agent SDK
   SessionStore, OpenAI Agents SDK, Google ADK, Mastra, LangGraph).
4. Memory-poisoning threat research aimed at I2 (sleeper poisoning, MINJA,
   ZombieAgent, OWASP ASI06).
5. Reported secret leaks into `~/.claude/projects` JSONL, secret scanners,
   and GitHub push protection.
6. End-to-end encrypted sync with delegable capabilities (Keyhive, Willow
   and Meadowcap, Jazz, Megolm, git-remote-gcrypt, p2panda).
7. SCITT receipts, Sigsum witnesses, and the new agent-specific
   tamper-evident logs.
8. Session identity in ACP, A2A and MCP, which sets the keys a cross-agent
   store must use.
9. OTel GenAI conventions and Claude Code's OTel export as a push
   alternative, and its conflict with I4.
10. Whether the record sits inside or outside a sandbox snapshot (E2B, Morph,
    Fly Sprites, Daytona, Modal, Docker).
11. EU AI Act logging and retention duties against crypto-shredding.
12. Which memory systems envelope or quarantine recalled content, given
    MINJA, AgentPoison and InjecMEM.
13. OTLP-fed trace stores beyond Langfuse (LangSmith, Phoenix, Weave,
    Braintrust, Laminar, Datadog, Honeycomb): retention, tamper evidence,
    export.
14. A systematic comparison of agent SDK session persistence: schema, fork,
    compaction, pluggability.
15. Git scaling numbers: reftable, SHA-256 interop, partial clone, notes
    fan-out, packfile growth, forge rate limits and ref caps.
16. Encrypted git transports compared on rotation, revocation and
    crypto-shredding (git-remote-gcrypt, git-crypt, age schemes, Keyhive,
    rclone crypt).
17. Where to flush the record when a cloud sandbox is killed (E2B, Morph,
    Daytona, Modal, Vercel, Cloudflare, Fly).
18. Vendor legal-hold exports (Compliance API, OpenAI retention, Copilot,
    Cursor, Devin) and how a local record reconciles with vendor deletion.
19. Redaction in share tools, and how redaction coexists with a hash chain
    that audits each redaction.
20. Patch-theory, scale and data VCSes (Pijul, Darcs, Sapling, Oxen, DVC,
    lakeFS, Xet) for concurrent append-only logs.

**What the sweep did not cover.** It did not measure anything: no git
scaling benchmarks, no push-limit tests, and only a few hands-on checks
(the Copilot trailer count is one). It did not survey the attack literature
on agent memory, so the I2 findings above rest on design reading, not on
tested exploits. It is Claude-heavy; other agents' formats appear only where
a system happened to read them. Closed vendors were read through their docs
and client code, so server-side retention and storage are often inferred.
Legal retention, sandbox snapshot boundaries and observability backends
were left as angles, not read.
