# The gates of ParleyInn's CI, defined once: ci.yml runs each through
# scripts/ci-gate.sh NAME and scripts/ci-local.sh runs the same list
# here, so a gate's command lives in this file and nowhere else. A check
# (ENG-27) fails CI when ci.yml runs a gate's command inline or a gate
# has no CI job. One gate a line, fields separated by |:
#
#   name    what ci.yml and the local runner call the gate
#   fit     fast (runs by default), full (runs with --full, needs the
#           room its "needs" names) or no (CI's runner only)
#   needs   why a gate that does not run here does not: - (nothing),
#           disk, network, parinn (a built release core), runner (a CI
#           runner's services or artifacts) or a tool
#   scope   ws (once), pkgs (once; {pkgs} is the touched crates as
#           "-p a -p b" here and "--workspace" in CI), crate (once per
#           touched crate, {crate}, {floor} its unit-line floor), tags
#           (once; {tags} is the requirement ids the diff touches) or
#           files (once; the drift cases the touched files inject)
#   ci      the command CI runs, or @job:NAME / @workflow:NAME when the
#           job or workflow is the gate's definition (its shards, decoy
#           HOME and artifacts are the job's own) and this file only
#           names it
#   local   the command here, or = for the CI command; @size is the
#           ENG-34 line limits through the review bundle
#
# A command holds no | character.
# name|fit|needs|scope|ci|local
